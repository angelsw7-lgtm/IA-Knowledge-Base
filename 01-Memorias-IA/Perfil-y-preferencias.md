# Perfil y preferencias

Información estable sobre cómo trabajar, comunicar y tomar decisiones.

## Preferencias de trabajo

- Prioriza herramientas abiertas, archivos propios y formatos duraderos frente a plataformas propietarias.
- Evita costes recurrentes cuando una alternativa gratuita y fiable cubre la necesidad.
- Prefiere una configuración práctica, verificada paso a paso, antes que explicaciones abstractas.
- Quiere que GPT, Claude y futuros asistentes puedan retomar el contexto desde una misma fuente externa.

## Estilo de comunicación

- Español como idioma de trabajo.
- Comunicación directa y orientada a avanzar: se valora que el asistente tome iniciativa razonable y explique las decisiones relevantes.
- Conviene distinguir los hechos confirmados de las inferencias, sobre todo al hablar de proyectos creativos o decisiones de negocio.

## Decisiones o principios duraderos

- La bóveda de Obsidian en Markdown es la fuente de verdad para conocimiento y contexto reutilizable.
- GitHub privado guarda la copia remota y el historial; no se usará Obsidian Sync mientras no aporte una necesidad real.
- Git es el mecanismo de versionado: hacer un commit con un mensaje claro después de cambios significativos.

## Valoración inicial del ecosistema de proyectos

### Observaciones confirmadas

- Hay varios frentes de trabajo identificados como ConcertSost, Sabor a Música, Vinal Fest, Fusion Town, Proyecto Marde, PATOS, Work y Personal.
- El entorno de trabajo incluye herramientas de producción o gestión de contenido audiovisual y musical, además de herramientas de IA.
- El reto principal no parece ser la falta de proyectos, sino conservar contexto, decisiones y próximos pasos entre varios proyectos y asistentes.

### Hipótesis de trabajo — validar

- Los proyectos podrían compartir una capa creativa, musical, cultural o de eventos. Si es así, conviene centralizar criterios de marca, contactos, formatos de entregables y aprendizajes repetidos en `03-Referencia`.
- La continuidad entre conversaciones es especialmente importante: cada proyecto debería tener un archivo breve de contexto y decisiones para poder retomarlo sin reconstruirlo desde cero.
- La prioridad inicial es reducir dispersión, no añadir complejidad: notas cortas, estructura consistente y revisión periódica son preferibles a un sistema excesivamente detallado.
